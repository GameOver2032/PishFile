# راهنمای مشارکت

از این‌که می‌خواهید به پیش‌فایل کمک کنید خوشحالیم! 💚

## گزارش خطا (Bug)

یک Issue باز کنید و این موارد را بنویسید:

- نسخه‌ی برنامه (تنظیمات ← درباره)
- مدل گوشی و نسخه‌ی اندروید
- مراحلی که به خطا منجر شد
- تصویر یا فیلم کوتاه از مشکل
- متن خطا اگر دیدید (Logcat)

## پیشنهاد قابلیت (Feature)

قبل از کدنویسی، Issue باز کنید و بگویید:

- چه کاری در حال حاضر انجام می‌دهید و چه چیزی کم است؟
- این قابلیت در کار روزانه‌ی دفتر شما چه سودی دارد؟
- اگر فرایند دستی دارد، آن را قدم‌به‌قدم بنویسید
- کدها و واحدهای نام‌گذاری، همگی فارسی/انگلیسی یکدست باشند

## قواعد کد

- زبان: **Kotlin**، همه‌جا با سبک رسمی (۴ فاصله).
- متن‌های رابط کاربری **فارسی** و توضیحات کد هم فارسی است.
- کامیت‌ها به سبک Conventional Commits:
  `feat(prefile): افزودن تخفیف پله‌ای` / `fix(installments): رفع محاسبه‌ی سررسید اسفند`
- نام شاخه: `feature/...`، `fix/...`، `docs/...`
- هر Pull Request باید:
  - فقط روی یک موضوع تمرکز داشته باشد
  - `./gradlew assembleDebug` را بدون خطا رد کند
  - برای تغییرات منطق کاری، تست واحد داشته باشد (مثلاً در `app/src/test/`)

## ساخت و تست

```bash
# ساخت
./gradlew assembleDebug

# تست‌های واحد
./gradlew test

# لینت کد (در صورت فعال بودن)
./gradlew lint
```

## ساختار افزودن یک فیلد جدید (مثال واقعی)

فرض کنید می‌خواهید «تعداد رادیاتور» به واحد اضافه شود:

1. `data/local/entity/UnitEntity.kt` → فیلد `radiatorCount: Int? = null`
2. `data/local/entity` → نسخه‌ی دیتابیس را بالا ببرید و مهاجرت بنویسید (`MIGRATION_3_4`)
3. `ui/viewmodel/UnitViewModels.kt` → در `UnitForm` و `toEntity/from` اضافه کنید
4. `ui/screens/units/UnitScreens.kt` → فیلد `NumberField` را در بخش «امکانات و ضمائم» بگذارید
5. `core/BackupManager.kt` → اگر مهم است، در `unitToJson`/`jsonToUnit` هم اضافه کنید
6. `docs/DATABASE.md` → جدول را به‌روز کنید

## کاری که بیشتر از همه کمک می‌کند

- تست روی گوشی‌های واقعی با نسخه‌های مختلف اندروید (۸ تا ۱۵)
- گزارش مواردی که متن فارسی یا اعداد در آن‌ها ناخوشایند نمایش داده می‌شود
- پیشنهاد فیلدهای تخصصی بر اساس تجربه‌ی واقعی کار پیش‌فروش املاک
- بهبود مستندات و ترجمه‌ی انگلیسی
